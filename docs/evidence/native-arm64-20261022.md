# Native arm64 multiselect — design and findings (2026-10-22)

Shipping form: `native/dist/tpm-multiselect-macos-arm64.zip`
`libtpm_ms.dylib` (95 KB, self-contained) + `run_tpm.sh` + Dobby licence + README.

**The game installation is not modified.** Injection uses
`DYLD_INSERT_LIBRARIES`, which TPM already permits:

```
com.apple.security.cs.allow-dyld-environment-variables  = true
com.apple.security.cs.disable-library-validation        = true
com.apple.security.cs.disable-executable-page-protection= true
```

That third entitlement is also why native code patching works here, while every
attempt under Rosetta (MonoMod, Dobby, Harmony) died at the write.

## Why not BepInEx

BepInEx on this game needs CoreCLR, and CoreCLR needs `com.apple.security.cs.allow-jit`,
which TPM does not carry. The only way to run it is a re-signed "shadow" .app, per
machine, per update — not distributable. The native mod has no runtime, so it needs
neither JIT nor re-signing.

## Flow

```
Left Shift in CursorModeSelect
  -> BuildLogic.StartGameDragSelect(Demolish)          rectangle drag select
  -> items tracked in CursorModeGameDragSelect.SetItemSelectedStatus
  -> CheckPromptProcessSelectedItems suppressed, used as the takeover point:
       LevelEditorGroupSelectionManager.SelectEntity(entity, true) for each item
       BuildLogic.PlaceItem(leader, false, false)       leader onto the cursor
       _bSelectionMoving = true
       SetupGroupLeader(leader)
       InitialiseChildEntitiesForMoving()
  -> every tick: ProcessMoveSelection(false)            whole group follows the cursor
  -> place mode ends:
       left click  -> FinaliseChildEntitiesForMoving()  commit
       right click -> ProcessMoveSelection(true)        snap back to the original pose
       then ClearAllSelectedEntities()
```

## The level-editor gate

`GameUtils.IsLevelEditorGroupSelectionAllowed()` short-circuits `Update`,
`OnPlaceEntityStart`, `OnPlaceEntityPlaced`, `OnPlaceEntityCancel` and
`LevelEditorGroupSelectionItemsCount` for callers that are not the level editor:

```asm
call GameUtils.IsLevelEditorGroupSelectionAllowed()
test al, al
je   return
```

The gate is bypassed **only by not using those entry points**: the mod calls the
ungated halves directly (`SetupGroupLeader`, `InitialiseChildEntitiesForMoving`,
`ProcessMoveSelection`, `FinaliseChildEntitiesForMoving`, `ClearAllSelectedEntities`).
No code bytes are modified and the gate itself is left alone.

## arm64 specifics

| Problem | Resolution |
|---|---|
| Polling `il2cpp_domain_get()` before the runtime starts crashes at random | wait 10 s, then poll |
| `il2cpp_runtime_invoke` aborts inside the generated invoker for these methods | call the method pointer with the IL2CPP instance ABI (`this, args…, MethodInfo*`) |
| Generic methods (`HashSet<T>.Count`, generic-base singletons) abort | read static/instance fields through `il2cpp_field_*` |
| `StaticGameSystem<BuildLogic>.Instance` getter aborts | read the `<Instance>k__BackingField` static directly |

## Destructive bug found and fixed

`CursorModePlaceItem.OnCancelItem(bool sell)` reaches the mod with `sell = true`
because the drag select is the Demolish flavour. Forwarding it verbatim sold the
selected items on right click. Now `sell` is forced to `false` and the tracked
entities are deselected through `SetItemSelectedStatus(item, false)` before the
group is dropped.

## Known limitation

The rectangle is evaluated by the game on tile bounds, so items straddling the
border can be included. Filtering by `_dragStartWorldPosition` /
`_dragEndWorldPosition` would tighten it; not implemented yet.
